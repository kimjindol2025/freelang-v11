## 16 → 17 핵심 진화

### 3절 — SPEC.airc 분리 (신규)
- **플랜(2절)** = 휘발성 토론. 변할 수 있다.
- **SPEC.airc(3절)** = 잠금. 변하면 안 된다. **별도 행위** (substep 아님).
- 역할: ① 현재 세션에서 클로드가 슬쩍 노선 바꾸지 못하게(계획 일관성) ② 다음 세션 인계 문서.
- 근거: `kim/airc/CODING-RULES.airc` rule-1이 이미 `리서치 → 플랜 → SPEC.airc → 태스크 → 구현 → 검증`을 명시. SPEC.airc는 처음부터 별도 단계였다.

### 8·13절 — 이중 PASS 게이트
- **8절**: 단락 검증 실패 → 다음 단계 진입 금지.
- **13절**: 통합 검증 실패 → 저장(커밋/푸시) 금지.
- "fail인데 다음 진행" 함정을 *시스템적으로* 차단. (사례: nael 빌드 4연속 fail — 게이트가 함정 차단.)

### 12절 — 통합 검증
- 단락(기능) 다 됐다 **≠** 시스템 전체 OK. 통합 검증을 단락 검증과 분리.

## 횡단 정책 (11절에서 계승, 전 절 적용)

17절은 *흐름 구조*다. 아래 정책 lock은 [CODING_RULES_11.md](CODING_RULES_11.md)에서 그대로 계승:

- **파일 수정은 Edit 도구만** — `sed -i` 금지(비가역).
- **검증 우회 금지** — `git --force` · `--no-verify` · `--no-gpg-sign` 금지.
- **핫픽스 금지** — 문제 시 해당 단락 처음부터 재시작(7·8·13절 게이트).
- **보안** — 비밀은 환경변수(.env)만, 평문 저장·커밋 금지. `X-API-Key` 외 헤더 금지.
- **의존성** — 새 외부 패키지 추가는 협의·문서화.
- **완료(14·15)** — 검증(13 PASS) 전 push 절대 금지. commit + push + (블로그) 모두 끝나야 완료.
