## 2. 원인 판정

**호스트 태스크 수 변동(추측)**. 기준 전체 시험은 3/3, 대상은 2/3 통과했다. 대상 3회차의 유일한 실패는 `tests/run-task931.sh`의 `process-limit-run-parallel`에서 `FAILED_SLOTS=20 SUCCESSFUL_SLOTS=0`인 경우다. 그때 시험이 읽은 `PARALLEL_USER_TASK_COUNT=3140`, 설정한 `PARALLEL_ULIMIT_U=3145`로 여유는 5개였다. 별도 `ps` 100회 표본의 원문은 `USER_TASKS_100_SNAPSHOTS_MIN=3132 MAX=3144 SPAN=12`였다. 이 시험의 FreeLang 입력과 생성 C에는 DB 호출이 없다. 성공 슬롯 수도 대상 1회차 3, 대상 2회차 9, 기준 3회 모두 3으로 흔들렸다. 기준 자체의 10회 추가 반복 중 한 번은 성공 슬롯이 2개였다. 호스트 변동과 실패 시점의 인과 관계를 직접 계측한 것은 아니므로 판정은 추측으로 표시한다.

DB 변경 세 가지를 각각 되돌린 별도 임시 작업본에서 동일한 기존 `run-task931.sh`를 제한값 변경 없이 실행했다. 실행 위치: 메인. 모두 공용 잠금 아래 실행했고 본 가지의 DB 코드는 바꾸지 않았다. 각 실행의 원문 필드를 한 줄로 모았다:

## 3. 고친 곳(파일:줄)

- `tests/run-db-regress.sh:1` 기준·대상 3회 비교, 실행 전후 프로세스·태스크 수와 `ulimit -u/-n`, 전체 시험 RC 및 요약 기록. 집계 스크립트는 유효 실행 전에 커밋했고 실행 중 수정하지 않았다.
- `docs/D-2-regress.md:1` 비교 원문, 판정, 최종 검증 근거 기록.
- `runtime/db.c`는 D-2에서 수정하지 않았다. `runtime/http_server.c`도 수정하지 않았다. 잠금 대기, 저장점, 길이 검사 중 원인 변경을 특정하지 못했으며 위 분리 시험에서는 모두 동일하게 통과했다.
