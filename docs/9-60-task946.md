## 2. worker 한도와 RSS

`examples/erp-vendors/app.fl:339`에서 worker 한도를 `16`에서 `128`로 바꿨다. 변경 전 20개의 동시 POST 중 일부가 503 `server busy`를 받았고, 앱 출력 한도도 16이었다. 설정을 128로 올린 뒤 기존 비교 시험 현행 3회와 기준 런타임 1회에서 각각 `POST_20/20`, `CONC_SUMMARY=8/8`을 확인했다. DB 코드와 기대값은 수정하지 않았다.

worker 128 앱을 포함한 같은 비교 실행을 돌리며 `/proc/<pid>/status`의 `VmRSS`를 50ms 간격으로 관찰했다. 아래는 실행 파일이 앱인 프로세스들의 RSS 합계 최고치다. 프로세스 수는 peak 시 샘플에 일치한 앱 프로세스 수다.

```text
APP_RSS_PEAK_KB=5476 PROCESSES=2
APP_RSS_PEAK_KB=6080 PROCESSES=2
```

최고 관측값은 `6080 KiB`다. 이는 해당 실행에서 관찰한 RSS 합계이며, 고유 물리 메모리 사용량으로 환산한 값은 아니다.

## 3. TASK946_FAST_SUMMARY 1/2 조사

실패한 구성요소는 `TASK942_LEGACY_RC`다. 집계기가 요구하는 기대 종료 코드는 `0`이고 실제 종료 코드는 `1`이었다. 해당 구성요소가 실행하는 명령은 다음과 같다.

```text
timeout --signal=TERM --kill-after=10s 1800s env FL_HTTP_WORKERS=0 bash tests/run-task938-load.sh <가림> <가림>
```

현행 실행 원문:

```text
LOAD_FAST_SUITE_RC=0
FDFIX_CASE=fd-limit RC=1 SIGNAL=0 ERROR=db-exec: unable to open database file (sqlite=14)
LOAD_DATABASE_IS_LOCKED=194
LOAD2_SUMMARY=9/10
FDFIX_SUMMARY=4/5
TASK942_LEGACY_RC=1
```

`FDFIX_CASE=fd-limit`는 `ulimit -n 4`를 적용하는 음성 시험이다. sqlite=14를 반환한 뒤 다음 출력처럼 복구되어, 단독 fd-limit 동작은 의도된 결과와 일치한다.

```text
FDFIX_RECOVERY_RC=0 ROWS=1
```

기준 런타임 비교는 저장소 시작 HEAD `5b620b4ee4f2232da44cc4a88c68879257b34036` worktree에서 같은 `tests/run-task938-load.sh` 입력으로 실행했다. 현행과 기준 간 `runtime/` 차이 확인은 `RUNTIME_DIFF_RC=0`이었다. 기준 실행 원문:

```text
BASELINE_LOAD_RC=1
LOAD_FAST_SUITE_RC=1
FDFIX_CASE=fd-limit RC=1 SIGNAL=0 ERROR=db-exec: unable to open database file (sqlite=14)
FDFIX_RECOVERY_RC=0 ROWS=1
LOAD_DATABASE_IS_LOCKED=178
LOAD2_SUMMARY=9/10
```

양쪽에서 같은 legacy load 조건이 실패했고, 원문 오류는 모두 `database is locked (sqlite=5)` 계열이었다. 잠금 오류 개수는 `194`와 `178`로 달랐지만 두 실행 모두 `LOAD2_SUMMARY=9/10`이다. 기준 비교에서 `LOAD_FAST_SUITE_RC=1`도 있었으나 현행은 `0`이었고, 본 TASK946 실패 원인으로 계수하지 않았다. 기존 기대값 유지, DB 코드 미수정.

## 4. 전체 시험 및 실패 분류


잠금 아래 한 번 실행했다.

```text

END_UTC=2026-10-29T13:41:44Z

FULL_FAST_RC=1

TASK942_POOL_RC=0

CGC_SYMBOL_SUMMARY=5/5

```

실패 항목과 원인 분류:

| 실패 항목 | 분류 | 근거 원문 |
|---|---|---|
| `TASK942_LEGACY_RC=1` / `LOAD2_SUMMARY=9/10` | DB 원인 | `LOAD_DATABASE_IS_LOCKED=194` 및 서버 로그의 `db-exec: database is locked (sqlite=5)` |
| `FDFIX_SUMMARY=4/5` | DB 원인(집계 의존 항목) | `LOAD2_SUMMARY=9/10`; fd-limit 복구 자체는 `FDFIX_RECOVERY_RC=0 ROWS=1` |
| `TASK946_FAST_SUMMARY=1/2` | DB 원인(legacy 항목 집계) | `TASK942_LEGACY_RC=1`, `TASK942_POOL_RC=0` |
| `FULL_FAST_RC=1` / `FULL_CHECK_RC=1` | DB 원인(하위 legacy 실패 전파) | `TASK946_FAST_SUMMARY=1/2` |

FD 음성 시험의 원문은 별도로 기록한다. 이는 낮춘 fd 제한에서 예상된 오류를 내고 복구하는 시험이다.

```text
FDFIX_CASE=fd-limit RC=1 SIGNAL=0 ERROR=db-exec: unable to open database file (sqlite=14)
FDFIX_RECOVERY_RC=0 ROWS=1
```

pool 결과 원문:

```text
LOAD_DATABASE_IS_LOCKED=0
LOAD2_SUMMARY=10/10
FDFIX_SUMMARY=5/5
POOL_SUMMARY=8/8
TASK942_POOL_RC=0
```

시험 기록은 유지했다. DB 코드와 시험 기대값은 바꾸지 않았다.
