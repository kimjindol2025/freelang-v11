## CAUSE

### 1. 거짓 성공 — 확정

`phase-c-full.yml`의 Jest shard 단계에 `continue-on-error: true`가 있습니다. Shard 2가 30분 timeout 되었지만 job과 전체 run은 성공으로 표시되었습니다. summary는 실패 문구를 출력할 뿐 `exit 1`을 실행하지 않습니다. Slack workflow도 실패를 경고로만 처리합니다.

### 2. 함수 미등록 63건 — 부분 확정

`stdlib-loader.ts`에서 `createHelpersModule()`과 `createPerfModule()`이 등록되지 않았습니다. 따라서 helpers의 advanced 함수와 alias가 구현되어 있어도 런타임에서 노출되지 않습니다. `createQueueHelpersModule()`은 중복 import·중복 등록되어 있습니다.

63건 각각의 함수명과 테스트 매핑은 `--silent` 로그 및 timeout 때문에 UNVERIFIED입니다.

### 3. 시간 계산 4건 — 계약 충돌 확정

`now()`는 ISO 문자열을 반환하고 `now_ms()`는 숫자 timestamp를 반환합니다. 시간 뺄셈 코드가 `now()`를 숫자로 가정하면 실패합니다.

### 4. `node:sqlite` 1건 — 원인 확정, 실제 테스트는 미확인

CI는 Node 20을 사용합니다. `stdlib-db.ts`, `stdlib-db-query.ts`, `stdlib-mariadb.ts`는 `node:sqlite`의 `DatabaseSync`를 사용하며 소스 주석은 Node.js v22.5+를 전제로 합니다. Node 20과 런타임 지원 조건이 맞지 않습니다.

### 5. `repeat` 1건 — 구조 문제 확정, 실패 호출은 미확인

`repeat`은 배열 반복, `str-repeat`은 문자열 반복입니다. 그러나 `str-repeat` object key가 중복 선언되어 있고 CI 로그에도 duplicate-key 경고가 확인되었습니다.

### 6. Stage1 1건 — workflow 결함 확정, 실제 실패는 미확인

`scan-and-verify`에서 생성한 `stage1.js` artifact가 `jest-full` job으로 전달되지 않습니다. Jest job은 checkout 후 일반 build만 실행하며 Stage1 artifact 다운로드나 Stage1 생성 단계를 실행하지 않습니다.

### 7. 30분 timeout — 확정

현재 실행과 이전 실행 모두 Jest Shard 2가 약 30분 후 timeout 되었습니다. 로컬에서 동일 shard 명령을 외부 timeout으로 실행했을 때 첫 테스트 이후 종료되지 않는 현상도 재현했습니다.

`errors.test.ts`의 `loop-forever`는 후보일 뿐, 단독 원인으로 확정하지 않았습니다.

## 최소 수정안

1. Jest, verify, regression의 실패를 최종 job의 non-zero exit로 집계합니다.
2. `createHelpersModule()`과 `createPerfModule()`을 loader에 등록하고 advanced alias 테스트를 추가합니다.
3. 시간 계산에는 `now_ms()` 또는 `time_diff()`를 사용합니다.
4. CI Node를 `node:sqlite` 지원 버전으로 올리거나 호환 adapter를 제공합니다.
5. 중복 `str-repeat`을 제거하고 `repeat`/`str-repeat` 계약을 명확히 합니다.
6. Jest job마다 Stage1 artifact를 다운로드하거나 Stage1 생성 단계를 포함합니다.
7. Shard 2를 별도 격리 실행해 실제 hang 테스트를 특정합니다. `loop-forever`를 현재 단계에서 확정 원인으로 사용하지 않습니다.
