실행 위치: `freelang-v11`. 23·25 서버 접속·실행 0회. 앱 입력은 읽기 전용으로 사용했다. 12회 부하 측정과 전체 fast 시험은 지정 flock 잠금 아래 순차 실행했다. 겹친 시험은 없었다.

## 4. 암호 함수 미구현 원인 조사

`hmac_sha256`, `base64_encode`, `base64_decode`, `aes_encrypt`, `aes_decrypt`, `scrypt_kdf`, `random_bytes` 구현은 추가하지 않았다. C 런타임과 x86 `c-runtime-name` 테이블에는 이 이름들의 native 구현·심볼 매핑이 없다. 반면 [JavaScript interpreter](https://github.com/kimjindol2025/freelang-v11/blob/v11-x86-seed-public/self/runtime/interpreter.js)에는 HMAC-SHA256, Base64, random bytes 구현이 있다. 그래서 기존 시험의 0/7은 x86 backend가 JavaScript interpreter의 crypto builtins를 제공하지 않는 데서 비롯된다. AES와 scrypt도 조사 범위의 C runtime 구현을 찾지 못했다. 암호 벡터나 기대값은 변경하지 않았다.
