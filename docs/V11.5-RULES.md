# FreeLang v11.5.x 언어 통일 규칙 (정식)

> **버전**: v11.5.0 (kebab-case alias) ~ v11.5.1 (시그니처 통일)  
> **상태**: 정식 표준 (호환성 1년 보장)  
> **목표**: v11의 33개 설계 결함 → 5가지 일관된 규칙으로 통합

---

## 🎯 5가지 통일 규칙

### 규칙 1: 함수 인자 순서 — "데이터 → 함수 → 부가"

**원칙**: 첫 인자는 항상 변환할 데이터(컬렉션/문자열/객체), 두 번째는 변환 함수, 셋째부터 부가 데이터.

**v11 (혼란)**
```fl
(map      fn  arr)         ;; 함수 먼저 (Clojure 영향)
(filter   fn  arr)         
(reduce   fn  init arr)    
(assoc    map k v)         ;; 이미 OK (컬렉션 first)
(cache-set k  v ttl)       ;; key first (비일관)
(swap!    ref fn)          ;; atom 먼저
(str-replace s old new)    ;; 문자열 first (이미 OK)
```

**v11.5.x (통일)**
```fl
(map      arr fn)          ;; 데이터 → 함수
(filter   arr fn)          
(reduce   arr fn init)     ;; 데이터 → 함수 → 초기값
(assoc    map k v)         ;; 그대로 유지
(cache-set cache k v ttl)  ;; 캐시 객체 명시
(swap!    ref fn)          ;; atom 그대로 (특수)
(str-replace s old new)    ;; 그대로 유지
```

**호환성**: v11.4.2 시그니처도 유지 (감지 로직으로 자동 판단)

| 함수 | v11 | v11.5.x | 감지 방식 |
|------|-----|---------|----------|
| map | (map fn arr) | (map arr fn) | fn이 함수형? → v11 방식 유지 |
| filter | (filter fn arr) | (filter arr fn) | 동일 |
| reduce | (reduce fn init arr) | (reduce arr fn init) | 동일 |
| sort-by | (sort-by fn arr) | (sort-by arr fn) | 동일 |
| find | (find fn arr) | (find arr fn) | 동일 |
| any? | (any? fn arr) | (any? arr fn) | 동일 |
| all? | (all? fn arr) | (all? arr fn) | 동일 |
| group-by | (group-by fn arr) | (group-by arr fn) | 동일 |
| unique-by | (unique-by fn arr) | (unique-by arr fn) | 동일 |
| index-by | (index-by fn arr) | (index-by arr fn) | 동일 |

### 규칙 2: 작명 — kebab-case 통일

**원칙**: 모든 함수명은 `kebab-case`(소문자 + 하이픈). snake_case는 deprecated alias로 유지.

**v11 (혼재)**
```fl
length, str-length         ;; 불일관 (둘 다 OK)
str_to_num                 ;; snake_case
json_parse                 ;; snake_case
now_ms                     ;; snake_case
mariadb_connect            ;; snake_case
http_get                   ;; snake_case
file_read                  ;; snake_case
auth_jwt_sign              ;; snake_case
server_start               ;; snake_case
```

**v11.5.x (통일)**
```fl
length                     ;; 간단히 (str-length는 alias)
str-to-num                 ;; kebab-case
json-parse
now-ms
mariadb-connect
http-get
file-read
auth-jwt-sign
server-start
```

**상태** (v11.5.0부터 적용)
- ✅ 400+ kebab-case alias 등록됨 (eval-builtins.ts)
- ✅ 두 형식 모두 동일 기능 (완전 투명성)
- 🟡 snake_case는 v11.5.1부터 deprecated 경고 (but 계속 작동)

**활성화**:
```bash
# 기존 코드는 그대로 작동
(str_to_num "42")    # → 42 (자동 호출)

# 신규 코드는 kebab-case 권장
(str-to-num "42")    # → 42
```

### 규칙 3: 술어 함수 — `?` suffix 통일

**원칙**: 불린 반환 함수는 `?`로 끝남. `is_X` 형식은 `X?`로.

**v11 (혼재)**
```fl
nil?                       ;; ✅ 이미 OK
is_array                   ;; snake_case + is prefix
is_string
is_number
file_exists                ;; verb + object (혼란)
fl_require?                ;; ✅ 이미 OK
keyword?                   ;; ✅
symbol?                    ;; ✅
empty?                     ;; ✅
```

**v11.5.x (통일)**
```fl
nil?                       ;; 그대로
array?                     ;; is_ → ? suffix
string?
number?
file-exists?               ;; -exists? 패턴
fl-require?                ;; 그대로
keyword?
symbol?
empty?
```

**구현 상태** (v11.5.0~v11.5.1)
- ✅ file-exists?, string?, array?, number? (alias 등록됨)
- 🟡 is_array, is_string 등은 deprecated (경고)
- 🔄 신규 술어 함수는 모두 `?` suffix (정책)

**예시**:
```fl
(if (file-exists? "path")
  (file-read "path")
  "")

(if (array? $data)
  (length $data)
  0)

(if (nil? $value)
  "없음"
  (str $value))
```

### 규칙 4: HTTP/I/O 응답 — 명시적 함수 분리

**원칙**: 응답 구조는 통합 반환(`{:status :body :headers}`), 하지만 편의 함수 제공.

**v11 (번거로움)**
```fl
;; http_get은 항상 {:status :body :headers} 반환
(let [resp (http-get "https://api.example.com/data")]
  (let [body (get resp "body")]
    (json-parse body)))   ;; 매번 추출 필요

;; 마찬가지로 파일/DB
(let [content (file-read "data.json")]
  (json-parse content))
```

**v11.5.x (명시적)**
```fl
;; 기본: 전체 응답 반환
(http-get "https://api.example.com/data")
;; → {:status 200 :body "..." :headers {...}}

;; 편의 함수 (Phase X-4에서 추가)
(http-get-json url)       ;; → JSON 객체 직접 반환
(http-status url)         ;; → 200
(http-body url)           ;; → "..." (body string)

;; 파일도 마찬가지
(file-read "data.json")            ;; → string
(json-parse (file-read "data.json")) ;; → object

;; 또는
(file-read-json "data.json")  ;; Phase X-4 추가 예정
```

**구현 타임라인**
- v11.5.0 ✅: http-get, file-read 기본 함수
- v11.5.1 🔄: http-*, file-* 편의 함수 추가 (Phase X-4)

### 규칙 5: 함수 선언 — `$` 접두사 폐지 검토

**원칙**: 매개변수는 원칙적으로 `$` 접두사 불필요. 호환성 위해 v11.5.x에선 선택.

**v11 (필수)**
```fl
;; $ 필수 — 변수와 함수를 구분하는 목적
(defn add [$a $b]
  (+ $a $b))

(let [[$x 10] [$y 20]]
  (+ $x $y))

(fn [$n]
  (* $n 2))
```

**v11.5.x (선택)**
```fl
;; $ 없이 작동 (신규 권장)
(defn add [a b]
  (+ a b))

(let [[x 10] [y 20]]
  (+ x y))

(fn [n]
  (* n 2))

;; $ 여전히 지원 (호환성)
(defn add [$a $b]
  (+ $a $b))  ;; → deprecated 경고 (but 작동)
```

**변경 이유**
- AI 입장: `$` 특수 기호는 혼동 야기 (Clojure, Scheme에 없음)
- 가독성: 불필요한 노이즈
- 동향: 다른 Lisp 방언 따라잡기

**호환성 보장**
- 기존 코드: `$a` 문법 그대로 작동 (deprecated 경고 X, v11.5.1~v11.6.0)
- 신규 코드: `a` 권장 (linter 제안)
- v11.7.0+: `$` 폐지 검토 (2027년 이후)

**마이그레이션**:
```bash
# --remove-dollar 옵션으로 자동 변환
freelang-migrate src/ --remove-dollar

# 또는 수동 (간단한 경우)
# [$a $b] → [a b]
# $a → a  (심볼/바인딩)
```

## 🛠️ 마이그레이션 도구 (freelang-migrate)

### 설치
```bash
npm install -g freelang-cli@12
# 또는 로컬
node bin/freelang-migrate --help
```

### 사용
```bash
# 1. 미리보기 (dry-run)
freelang-migrate src/ --dry-run

# 2. 모든 규칙 적용
freelang-migrate src/ --apply

# 3. 선택적 적용
freelang-migrate src/ --no-arg-order      # 규칙 1 제외 (인자 순서)
freelang-migrate src/ --no-dollar         # 규칙 5 제외 ($ 제거 안 함)
freelang-migrate src/ --only-kebab        # 규칙 2만 (작명)
```

### 출력 예시
```
[Scanning src/...]

  Line 12: (str_to_num "42") → (str-to-num "42")
  Line 18: (json_parse body) → (json-parse body)
  Line 25: (map (fn [$x] (* $x 2)) arr) → (map arr (fn [x] (* x 2)))

[src/api.fl]
  Line 8: (mariadb_query db sql) → (mariadb-query db sql)
  Line 15: (file_exists path) → (file-exists? path)
  ...

총 변환: 47개
? 모두 적용? [Y/n]: Y
✓ 백업 생성: src/.v11-backup/
✓ 변환 완료
```

### 옵션
```
--dry-run           미리보기만 (파일 미수정)
--apply             실제 변환 + 백업 생성
--no-arg-order      인자 순서 변환 제외
--remove-dollar     $ 제거 활성화
```

## ⚠️ 주의사항

### 인자 순서 변환 (규칙 1) — 가장 위험
- **이유**: 감지 로직에 실수 가능성 (고차 함수 vs 일반 함수 구분)
- **권장**: 먼저 코드 읽어보고, 필요 시 수동 수정
- **안전 옵션**: `--no-arg-order`로 제외

### $ 제거 (규칙 5) — 선택 사항
- **이유**: let 바인딩에서 `$var` 제거 시 변수명 충돌 가능
- **권장**: 프로젝트별로 판단 (키 이름과 겹치지 않으면 OK)
- **수동**: 필요한 함수만 수동 수정

### 혼합 코드 (일부 kebab, 일부 snake_case)
```fl
;; 위험: 같은 함수를 두 이름으로 호출하면 중복 변환 가능
(let [result (str_to_num "42")]
  (str-to-num "100"))  ;; 둘 다 작동하지만, 변환 후 혼란

;; 권장: 통일 후 진행
```
